### The consequence that matters: identifying the Project is not proving a creation
The "new conversation -> first message" route and the "old conversation picked in the sidebar" route end in URLs of exactly the same shape (test: `project-hardening.test.js`), and the Project page has the same URL before and after "new chat". So `/project` -> `/c/<uuid>` inside the right Project proves nothing about *when* the conversation was created. Before this hardening the first version bound on that transition alone; an old conversation opened from the sidebar would have been attached to the workspace.

Now: `creation.js` checks the Project id (identification) and, separately, asks an injected `evidence(viewId)` for an independent sign of a first send. **No such sign has been verified, so none is wired**: every Project conversation ends as `unconfirmed-origin`. The page stays on screen in its workspace with a note on its tab ("nada comprova que foi criada agora... Gerenciar > Vincular conversa atual") and the user binds it with the ordinary I3A flow. Passive signals that might become evidence (a `responding` observation right when the id appears; a draft that was present on the Project page and then disappears) were considered and not adopted: they can also occur for an old conversation, and the observation hub is not allowed to read content.

### Recovery of the temporary page
If the intent ends with `context-changed`, `project-changed`, `outside-project`, `navigated-away` or `already-bound`, the page is **released** to "Sem workspace" (`navigator.releaseToUnbound`): same view, draft and activity, still on screen if it was being looked at, bindable later. `already-bound` is adopted by the binding it belongs to. `unconfirmed-origin` and `refused:*` keep it in the workspace with a note. A page that belongs to a binding (suspect, orphan, unverified) is never released.

### Harness reliability: root cause and fix
**Root cause (proved by a sanitized failure snapshot, run hd4):** a harness race, not a product regression and not an authentication limit. The harness makes each logged-out page "be" a conversation with `history.pushState`. The logged-out SPA later redirects an unavailable conversation back to `/` (the behaviour already documented in chat-views/manager.js). For the FIRST page of a run (cold session, slowest boot) that redirect sometimes arrives after the pushState, so the view of "Code Review" went back to `identity: pending, relation: left` while the other three kept their address. The product then correctly treated it as a temporary conversation ("Nova conversa"), which is why the two checks (notice, activity center) failed with "Nova conversa" instead of "Code Review". The renderer script error that ended the run followed from that state. It explains why base `8061d60` failed the same way and why earlier runs sometimes passed (the redirect won or lost the race).

**Fix (harness only, no production change):** `bePage` now asserts the address, requires it to still be there after the page had time to run, and asserts again if it was undone (condition-based with up to 6 attempts; retries are reported in `steps.pageRetries`); `keepPages()` re-asserts before the checks that depend on the pages; each page-address assertion is now a check of its own (29 checks instead of 25); every failed check carries a sanitized snapshot of the views (ids, scope, identity state, relation, page state, address shape with ids blanked; no content); the report records `lastCheck` for fatal errors.

**Runs after the fix (all kept):** 5 consecutive runs, 29/29 checks, exit 0 each; page 1 needed one re-assertion in 3 of 5 runs (so the race is real and now handled), none in the others. Before the fix: 3 consecutive runs 12/14 + fatal error (exit 1), and the base commit failed the same way. Exit codes keep the contract (0/1/2/3/77); failures were observed to exit 1.

**Classification:** harness bug (race against the logged-out SPA redirect). Limitation that remains: the harness exercises a logged-out ChatGPT, so it proves the ContextDeck plumbing (views, observation, overlay, IPC), not behaviour that needs an authenticated account (Projects, real generation).

## Workspace-first association (supersedes the "Sem workspace" box and the creation-evidence rule)

Product decision: ContextDeck is workspace-first. **A conversation opened inside a workspace is bound to that workspace**, unless it already belongs to another one (then the user is warned and decides). Users do not manage a category of loose conversations.

### Contract (implemented in `chat-bindings/context-adoption.js`, `ChatBindingsService.adopt`, navigator `contextViews`)
| Situation | Result |
| --- | --- |
| New conversation started with "Nova conversa" in A, id appears (even if B is selected by then) | bound to **A** (the context captured at the click); same view; origin `context` |
| Old unbound conversation opened (sidebar/link) in A's page that is on screen | bound to A |
| Already bound to A | reused (`expectedKey`), no new binding, no new view |
| Bound to B, opened in A | **no change**; banner: "Esta conversa pertence ao workspace B. Você está em A." with *Ir para B*, *Transferir vínculo…* (second click confirms; I3A reassignment), *Voltar* (the page moves to B's workspace, A shows what it showed) |
| No id yet | "Nova conversa", nothing invented; evaluated when an id appears |
| Hidden page changing route, reload, redirect, late event, restored view | passive: never binds |
| Destination not verifiable (workspace suspect, Herdr disconnected, limit) | pending: page stays in A with a note and "Tentar vincular"; a pending creation completes by itself when the destination is verifiable again |

Safety: `adopt` is only called from the main-side adoption service; there is no IPC that takes a destination or `targetChosen` for it (`chatnav:resolve` takes a page id and one of retry/go/transfer/back). `adopt` still requires a live verified workspace, refuses a `suspect` workspace, never moves an existing binding (conflict) and does not need the selection to match (the context was captured at the click). Auto mode: the click is the intent; a later passive focus change is not.

### UI
No permanent "Sem workspace" section or "Conversa não vinculada" tabs. The activity center lists pages that live in no workspace **only if some exist** (opened while no workspace was selected): exceptional, no management actions; opening one while a workspace is selected puts it in that workspace's context (the user's act). Binding form for loose conversations, `activity:bind-unbound` / `activity:new-unbound` and `unbound.js` bind/create were removed. Tabs without a label read "Conversa"; "Nova conversa" while there is no id. The bar title is `ChatGPT · <workspace label from Herdr>`; the label is Herdr's (if it shows a folder name, that is the workspace's name in Herdr).

### Projects
"Nova conversa" in a workspace with a Project opens the Project page in A's context; whatever conversation appears there (new, or old picked in the sidebar) is bound to A by the same rule. A local binding is **not** proof of creation inside the Project, and the ProjectBinding is never modified. The `evidence` hook of the previous hardening was removed because the question it answered is no longer asked. Project identity (Project id in the address) is still validated when linking.
