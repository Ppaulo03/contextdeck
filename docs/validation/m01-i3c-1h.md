## Findings and evidence

| Finding | Diagnosis in starting code | Current treatment |
| --- | --- | --- |
| F-01 | The state probe reported only composer text length as `draft`; it had no attachment/upload signal. `blockers()` treated `draft: empty` as sufficient. | Mitigated conservatively. The isolated-world one-shot check reports populated file inputs and upload/progress markers as `present`; all other states return `unknown`. Authenticated DOM absence markers are not validated, so real views remain ineligible for suspension. |
| F-02 | `manager.suspend()` wrote the suspended record and removed the entry before `destroy()`, ignored exceptions and returned success without checking liveness. | Corrected. Entry stays managed in `SUSPENDING`; success requires the destroyed event or `isDestroyed()`. Exceptions/timeouts on a still-live handle restore the entry and return a refusal. |
| F-03 | `workspaceStatus()` treated either a matching label or matching directory as enough; same ID + name with a changed directory could be linked. Missing recorded evidence or any label/directory mismatch is `suspect`, requiring explicit reconfirmation. ChatBindings and ProjectBindings data are preserved. Automatic adoption is restricted to linked workspaces. Same ID + label + cwd after recreation remains indistinguishable. |
| F-04 | The destroyed event marked the entry but did not delete it; `list()` filtered it while the handle remained in `entries`. | Corrected. | F-05 | Suspended records were memory-only; an unbound residual had no binding-based restart recovery path. | Corrected by policy: residual pages cannot be suspended. They remain live and available in the exceptional list until bound or the app closes. No residual catalog was added. |
| F-06 | Main-frame navigation allowed any HTTPS origin. | Hardened to HTTPS ChatGPT and current login provider origins. Other embedded main-frame origins are blocked; popup policy remains sandboxed and denies other destinations. Actual authenticated redirects remain pending manual validation. |

## Changes and contracts

- Suspension stays explicit and is never scheduled automatically.
- A conversation can be suspended only with a persistent ChatBinding. ProjectBindings remain separate and untouched.
- `manager.suspend()` is asynchronous and only reports success once destruction is observed. The `chats:suspend` IPC contract remains unchanged.
- A live handle after failed destruction remains under manager ownership and can be retried. A restored binding uses the existing URL and persistent Chromium partition.
- Main-frame ChatGPT navigation stays in the isolated WebContentsView with no preload, Node access, remote IPC, cookies, or network interception.
- Herdr reads and explicit `workspace.focus` behavior are unchanged. Identity disagreement requires explicit reconfirmation; no binding is deleted or rewritten automatically.
- Authenticated views currently fail the conservative unsent-state check because absence of staged attachments is not provable from a validated public DOM surface. This is intentional until manual inspection and a reliable signal exist.

- F-05: residual pages stay live and cannot be suspended; binding a residual makes it a normal conversation tab.

- F-08: 100 suspend/restore cycles keep observer and manager bookkeeping bounded.
