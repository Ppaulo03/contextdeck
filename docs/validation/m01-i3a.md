# M01-I3A — Chat contexts and persistent associations

Date: 2026-10-11 · Windows 11 · Node 24.14 · Electron 44.7.0 · branch `feature/m01-i3a-chat-context-bindings`, based on the last commit of the I3P branch · Herdr 0.9.3.

Scope: persistent associations between Herdr workspaces and ChatGPT conversations (several per workspace), their validation and management UI. **Not** in scope and not done: several `WebContentsView`s, navigation between conversations, unloading, runtime indicators, automatic binding after the first message, any Herdr focus command. Decision record: [0002](../decisions/0002-chat-bindings.md); architecture: [architecture.md](../architecture.md#chat-bindings-m01-i3a).

Legend: **Auto** = automated suite · **Harness** = script driving real Electron against a throwaway profile and a fake Herdr (no Herdr session touched, no message ever sent, logged-out chatgpt.com) · **Manual (pending)** = needs the project owner at the keyboard, logged in, real Herdr · **Blocked** = cannot be validated by this work.

## A. Diagnosis (starting point)

| Topic | Finding | Consequence |
|---|---|---|
| Persistence | `ui-state.json`: preferences rewritten whole by `sanitize()`, which drops unknown fields and falls back to defaults on any error; non-atomic best-effort write | Unsuitable for user-authored data → own file ([0002](../decisions/0002-chat-bindings.md) §4) |
| Herdr contracts | Workspace ids `w<n>` unique per session, never reused inside a running session, stable across a server restart ([m01-i1.md](m01-i1.md)); selector `selected` has an `origin` (`dock`/`herdr`/`recovery`) and the "current" workspace is an estimate | Identity = session + id; destination must be acknowledged when it is only an estimate |
| **Session identity** (investigated) | `herdr session list --json` returns `name`, `socket_path`, `session_dir`, `default`, `running` and nothing else; the snapshot has no session/server UUID. A deleted-and-recreated session of the same name restarts at `w1` | **A session cannot be verified across recreation.** Mitigation: per-workspace recovery record (label + directory); id present but both differ → `suspect`, never silently trusted. Residual risk below |
| Chat view lifecycle | One `WebContentsView` created once by `chat-view.js`; the URL is available in main (`contents.getURL()`); SPA navigation arrives as `did-navigate-in-page` | The current address is read in main; the view is not touched |
| I3P observer | Opt-in, diagnostic; hashes in its log are not identifiers; `ended-unclassified` is a `reason` of `unknown` | Runtime contract promotes it to a first-class state; nothing persistent depends on the observer |
| Overlay | A local view above the ChatGPT view, idle-released after 30 s, opened with an anchor | Reused as a second mode for the bindings panel (no new view) |
| Design system | Tokens, `.btn`, `.control`, `.menu*`, `.badge`; styles are token-driven (test-enforced) | The panel uses them; new CSS has no raw colors/z-index |

## B. Model

See [architecture.md](../architecture.md#chat-bindings-m01-i3a) for entities, invariants and statuses. In short: `ChatBinding` (persistent) · `WorkspaceChatContext` (bindings + recovery record) · `ChatRuntime` (contract only). Identity of a conversation = UUID in the URL (`/c/<uuid>` ≡ `/g/<project>/c/<uuid>`); identity of a workspace context = Herdr session name + workspace id. Pages without a durable id are *identity pending* and cannot be bound.

**Conflict policy.** Same conversation, same workspace → `already_bound`. Same conversation, other workspace → `conflict`; moved only by `reassign` with `confirmReassign: true` and a verified, acknowledged destination. A change of the selected workspace while a form is open → `context_changed`, nothing written. Estimated destination → `confirmation_required` until the user ticks the confirmation.

**Orphans.** A workspace missing from a connected Herdr leaves its bindings as `orphan`: kept in the file, listed in the panel with the old workspace name, adoptable (`reassign`) or removable (`unbind`). Herdr disconnected → `unverified` (never orphan); another session → `other-session` (kept, never judged); recreated session → `suspect`.

## D. Interface

The top-bar chat-only indicator that used to say "Chat sem projeto" is now a button reflecting the real state: **Vinculado: w1 · api** (bound to the selected workspace) · **Vinculado a w2 · app** / **a workspace ausente** (elsewhere) · **Chat sem vínculo** · **Identidade pendente** (new chat or non-conversation page). Clicking it opens the panel (overlay mode `chats`, above the ChatGPT view):

1. **Destino** — a workspace dropdown (default: the selected one) with its origin ("escolhido no ContextDeck" / "estimado pelo foco do Herdr" / "restaurado"); a confirmation checkbox when the destination is an estimate or differs from the explicit selection; a banner and blocked buttons if the selected workspace changed since the panel opened ("Usar o selecionado agora" reviews it).
2. **Conversas deste workspace** — label, category, status, how it was bound; **Editar** (inline label/category), **Desvincular** (two clicks; says the ChatGPT conversation is untouched).
3. **Vincular** — label + category, **Vincular conversa atual** (address read by main; disabled with the reason when the page has no durable id) and **Vincular por URL** (validated by main).
4. **Conflito** — where the conversation lives now; **Reassociar para …** is the only way to move it.
5. **Vínculos órfãos** — preserved bindings of vanished workspaces; **Reassociar aqui** / **Desvincular**.

Nothing in the panel selects a workspace, and the app never sends `workspace.focus` because of a binding.

## F. Manual homologation (Windows)

Preparation: `npm start` on the real profile (back up `%APPDATA%\Project Dock M00\ui-state.json` first; `chat-bindings.json` is created on the first binding). Use three real ChatGPT conversations C1, C2, C3 (existing, with ids in their address) and a "new chat" N. Do not delete any real conversation.

**A — Basic association**
1. Terminal tab: pick workspace A in the selector. ChatGPT tab: open C1.
2. The indicator reads *Chat sem vínculo*. Click it → destination shows A ("escolhido no ContextDeck"). Label "C1", category Arquitetura → *Vincular conversa atual*. Expect "Conversa vinculada" and the indicator *Vinculado: A*.
3. Open C2 in ChatGPT (indicator → *Chat sem vínculo*), bind it to A as "C2", Revisão.
4. Open the panel: A lists C1 and C2 with their categories.

**B — Isolation and conflict**
1. Select workspace B. Open C3 → bind to B. Open C1: the indicator reads *Vinculado a A · …* (not B).
2. Panel → *Vincular conversa atual* for C1 with destination B: expect the **Conflito** box naming A and the original label; nothing changed yet.
3. *Reassociar para B* → C1 now listed under B, gone from A; label/category kept.
4. Repeat binding C3 again to B: expect "já está vinculada a este workspace".

**C — Persistence**
1. Close and restart ContextDeck. ChatGPT tab: you are still logged in.
2. Panel: A and B show the same conversations. The Herdr workspace did **not** change by itself (check the Terminal tab). The first panel use after restart shows the destination as "restaurado (estimativa)" and asks for the confirmation checkbox before binding.

**D — Safety**
1. *Vincular por URL* with `https://example.com/c/…`, `http://chatgpt.com/…`, `javascript:…`, plain text: each is refused with a message; nothing is written.
2. Open a new chat N (address `https://chatgpt.com/`): the indicator reads *Identidade pendente*; *Vincular conversa atual* is disabled and the panel explains the chat must receive its own address first. Send nothing automatically.
3. Close workspace B in Herdr (a disposable one, not `default`): reopen the panel on A — B's conversations appear under *Vínculos órfãos* with "era de B · …". Reassociate one to A, leave one orphan, restart: it is still there.
4. With the panel open on A, change the selected workspace in the top bar's selector or in Herdr (Auto mode): the panel shows the "mudou desde que este painel foi aberto" banner and the bind buttons are disabled until you press *Usar o selecionado agora*.
5. Disconnect Herdr (stop its server for a disposable session only): the panel says Herdr is disconnected and refuses writes; bindings show as *não verificado*, not as orphans.
6. Confirm `chat-bindings.json` still has every binding and that no `*.corrupt-*` file appeared during normal use.

Report each item as confirmed / partial / failed, with the date.

## G. Limitations

1. **Recreated Herdr session.** No session UUID exists; a recreated session whose workspace reuses an id *and* happens to keep the same name or directory is treated as the same workspace. A mismatch of both is flagged `suspect`. Treat `suspect` as "re-confirm".
2. **Auto mode estimate.** Herdr's focus is session-wide; the destination of a binding is whatever the user confirmed in the panel, never inferred silently. Git directory is not used as identity.
3. **Project URLs** are modelled, not validated; strict UUIDs.
4. **Only `chatgpt.com`** (not `chat.openai.com` or `www.`).
5. **No automatic binding** after the first message of a new chat; no navigation between bound conversations; no indicators of generation/draft/attention (the contract exists, nothing consumes it).
6. **Panel access only from the ChatGPT tab** (the indicator is chat-only); orphans can be managed there.
7. The panel is a modal overlay: any window resize or tab switch closes it (existing overlay behaviour); an unsubmitted label is lost.
8. 300 bindings / 40 per workspace are guard rails, not product limits.

## H. Strategy for M01-I3B / I3C

- **I3B:** add a runtime manager that implements `getRuntime(bindingId)`/`subscribe`, one runtime per binding; add `lastSelectedBindingId` per workspace context as new optional fields (schema 2 with a migration, backup first); navigation between bound conversations by address (`url` from the binding), one view per runtime. The stored fields a manager needs already exist (`bindingId`, `url`, `conversationKey`, `workspaceIdentity`, `role`).
- Auto-binding after the first message can reuse `describeCurrent` (a pending page that acquires a durable id inside the same view) but must still go through the write guard and an explicit user action.
- **I3C:** eviction only behind the I3P `lifecycleAdvice` plus user policy; bindings are unaffected by unloading (they hold addresses, not pages).
- Observations from `fromObserverState` stay transient: attention/generation/draft are never added to the file without a recovery policy.
