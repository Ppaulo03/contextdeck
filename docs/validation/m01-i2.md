# M01-I2 validation — workspace selector and bidirectional focus sync

Date: 2026-10-10 · Windows 11 · Node 24.14.0 · Electron 44.7.0 · Herdr 0.9.3 (protocol 22).

Scope: a workspace selector in the top bar that (1) moves Herdr's focus when the user picks a workspace in ContextDeck and (2) follows the focus when the user switches workspace in the Herdr TUI. Nothing else changes: no conversation association, no Git behaviour tied to the workspace, no workspace creation/rename/removal.

Legend: **Auto** = automated suite · **Harness** = script driving the real Electron app against a real Herdr server (disposable session `m01i2-lab`, throwaway profile) · **Pending** = needs the project owner.

## 1. Architectural premise

ContextDeck is normally the **only** Herdr client of its session, so Herdr's session-wide focus is *usually* the workspace shown by our own client. The API cannot prove it (no per-client focus, see [m01-i1.md](m01-i1.md)); therefore the sync is **optimistic** and is never presented as an identification of our client. The main bar shows no certainty claim; the uncertainty (and the reliability of the last observation) stays in the diagnostics panel.

## 2. The focus command (verified)

`workspace.focus` is the only write the app performs, through `ApiClient.focusWorkspace(id)`; `request()` remains limited to the read allowlist.

```jsonc
// request
{"id":"cd-7","method":"workspace.focus","params":{"workspace_id":"w3"}}
// reply (≈2 ms): the workspace as Herdr now reports it
{"id":"cd-7","result":{"type":"workspace_info","workspace":{"workspace_id":"w3","number":3,"label":"docs","focused":true,"pane_count":1,"tab_count":1,"active_tab_id":"w3:t1","agent_status":"unknown"}}}
// side effect: workspace_focused, tab_focused, pane_focused events (no client id)
// already focused: same reply, NO events
// unknown id:  {"error":{"code":"workspace_not_found","message":"workspace w99 not found"}}
// bad params:  {"error":{"code":"invalid_request","message":"invalid request: missing field `workspace_id` …"}}
```

- The id is validated before it can reach the pipe (`^[A-Za-z0-9][A-Za-z0-9_.:-]{0,63}$`); a reply that does not confirm the requested workspace is an error (`unexpected_response`).
- **Effect on other clients (documented limitation):** `workspace.focus` moves the focus of **every** client attached to the session (measured in M01-I1, scenario D). With ContextDeck as the only client this is invisible; with a second client attached it will move that client's view too. No confirmation is asked per switch in the normal single-client case.

## 3. State model

The selection controller (`src/main/herdr/workspace-selection.js`) keeps these apart:

| Field | Meaning |
|---|---|
| `selected` | What the selector shows: `{workspaceId, origin}`; origin `dock` (picked in ContextDeck), `herdr` (followed the observed focus) or `recovery` (resolved after startup/reconnect). |
| `pending` | A user request not yet reconciled. Observations are recorded but never overwrite `selected` meanwhile. |
| `observedId` / `reliability` | Session focus in the latest authoritative snapshot; `only_workspace` (certain) or `last_writer` (estimate) or `none`. |
| `unavailableId` | A selected/saved workspace that no longer exists. |
| `mode` | `auto` (default) or `manual`. |
| `connection`, `lastError`, `options` | From the observer (M01-I1) and the last failure. |

### Rules that keep it loop-free

1. **Only `select()` sends `workspace.focus`**, and `select()` is reachable only from the user's `change` event in the dropdown. Observing, reconciling, reconnecting, switching mode and restoring preferences never send a command.
2. The dropdown is updated by assigning `select.value` (which does not fire `change`) behind an `applying` guard; a structure test pins that the single `herdrSelectWorkspace` call site lives in the `change` handler.
3. While a request is pending, snapshots are recorded in `observedId` but do not touch `selected`.
4. A request is bound to a token and to the observer's connection **epoch** (it increments when the connection is established or lost). If the connection changed or `stop()` ran, the late completion is dropped (`stale`) and the selection reverts; the command is **never replayed**.
5. After the command, state is confirmed by a snapshot read that **started after** the command (`observer.refresh()` guarantees this; a read already in flight is not enough).
6. Concurrent requests are refused (`busy`); selecting what is already shown and observed is a no-op.
7. No debounce is used for correctness; the observer's 300 ms coalescing only limits how often events cause a re-read.
8. Only explicit selections (origin `dock`) are persisted, bound to the session name; inferred ones never are.

### Flows

- **ContextDeck → Herdr:** validate session identity and that the workspace exists in the current model → mark pending (optimistic selection) → `workspace.focus` → fresh snapshot → clear pending, persist, compare. If someone else moved focus in between: auto follows the observed one, manual keeps the user's choice. On refusal or failure the previous selection is restored, the error is shown discreetly and the list is refreshed.
- **Herdr → ContextDeck:** a focus event only signals; the observer re-reads the snapshot; in **auto** mode the selector follows `observedId` (origin `herdr`), in **manual** it does not. No command, no PTY restart, no change to the ChatGPT view.
- **Startup / recovery:** manual restores the saved selection if it still exists (else shows it as unavailable); auto shows the observed focus (a saved selection never overrides what Herdr already shows, and never causes a `workspace.focus`). After a reconnect the list is reconciled, local preferences are kept and old operations are invalidated. A removed workspace is shown as unavailable and another can be picked.
- **Sync mode** (Auto default, Manual) is persisted. Manual → Auto adopts the observed focus without a command.

## 4. Interface and IPC

Top bar: `Workspace: [ w4 · name ▼ ] [Auto]` (native `<select>`: keyboard navigation for free; id always shown so homonymous names stay distinct; busy indicator and `aria-busy` while pending; disabled with "Herdr desconectado" when not connected; failures go to the existing footer notice). The Workspaces diagnostics panel stays and gained rows for mode, selection/origin, pending, observed focus and reliability, and the last selector error.

New IPC channels (contract pinned by tests): `herdr:select-workspace` `{session, workspaceId}` and `herdr:set-sync-mode` `{mode}` (invoke, sender-checked; only plain strings are forwarded, everything else becomes `null` and is refused in main). `herdr:state` now carries the observer state plus `selection`. There is no generic Herdr channel; no other Herdr method can be sent (a test scans main for forbidden method names and requires `workspace.focus` to be named only in `api-client.js`).

## 7. Limitations

- **Multiple clients:** the selector follows the last client that moved focus, not necessarily ours. Manual mode avoids unwanted following; an explicit choice moves every client. The app does not try to detect the number of clients (the API cannot tell).
- Rapid consecutive choices are not queued: while one is pending, further ones are refused with a notice.
- The workspace directory shown in diagnostics follows the active tab pane's cwd.
- Not captured by the harness: the open list of the native `<select>` over the ChatGPT view.
- Protocol 22 / Herdr 0.9.3 only.

## 8. Manual homologation checklist (Windows)

1. Start ContextDeck with a Herdr session that has 2–3 workspaces: the dropdown lists them as `id · name` (same-named workspaces are distinguishable); mode shows **Auto**.
2. Pick another workspace in the dropdown: the Herdr view switches; panes, tabs and running agents are untouched; the terminal is not restarted.
3. In the Herdr TUI switch workspace (mouse or keys): the dropdown follows; nothing is sent back (no flicker, no bouncing).
4. Open the dropdown while the **ChatGPT** tab is active: the list is visible over the page; keyboard navigation (↑/↓/Enter) works.
5. Hold/spam dropdown choices: it stays consistent; a notice may say a switch is still in progress.
6. Click **Auto** → **Manual**: TUI switches no longer move the dropdown; an explicit choice still works.
7. Close and reopen ContextDeck: manual shows your last explicit choice without moving Herdr; auto shows what Herdr shows.
8. Close the selected workspace in Herdr (manual mode): the dropdown says it is unavailable and lets you pick another.
9. Open **Workspaces** (diagnostics): selector mode/origin/observed focus/reliability are visible there.
10. No regressions: `Ctrl+Tab`, ChatGPT login, clipboard, Git Diff/Show/ZIP, terminal input.
11. (Optional) attach a second Herdr client and confirm you understand the limitation above.
