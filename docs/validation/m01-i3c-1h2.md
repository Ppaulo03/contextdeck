## State contract and protections

The lifecycle contract remains `present | empty | unknown`. The production probe currently emits `present` or `unknown`; it **does not emit `empty`** until a bounded, authenticated surface can prove both that the correct composer is found and that it has no staged item or upload in flight.

Suspension still requires an accepted fresh observer reading, known draft and generation states, a matching durable conversation identity, all prior lifecycle protections, and a fresh unsent result of `empty`. Stale/out-of-order observer results, missing forms, probe errors/timeouts, file selection and upload progress cannot authorize destruction. If unknown unsent state is the sole blocker, the UI offers **Verificar e suspender** to run the required fresh check; it is not a force-suspend option. There is no automatic suspension.

## Sanitized diagnostic trace

Run from PowerShell with the authenticated app closed:

```powershell
$env:CONTEXTDECK_COMPOSER_TRACE = '1'
npm start
```

The opt-in trace is written to `%APPDATA%\Project Dock M00\diagnostics\composer-trace.jsonl`. Schema 2 uses the existing per-view observer poll; it creates no additional observer or polling timer. It records a technical view ID, composer/draft/unsent enums, bounded editable ancestry and structural counts, view visibility, probe outcome/latency, changed lifecycle eligibility/reasons/verification availability, and navigation origin/policy result. The origin excludes path, query and fragment. See the [authenticated trace follow-up](m01-i3c-1h2-authenticated-trace.md) for the schema and collection steps.

The serializer rebuilds records from an allowlist. It drops message/draft text, filenames, paths, file bytes, cookies, tokens, complete URLs and arbitrary DOM values. Do not enable `CONTEXTDECK_CHAT_TRACE` for this collection: that is a separate, broader discovery trace. Send only `composer-trace.jsonl`; no screenshot or raw browser data is needed.

## Short authenticated manual protocol

Use the trace above, an authenticated profile, and only a disposable file. Keep the ChatGPT view alive during blocked cases. Record which scenarios were executed by a person; do not mark automated fixtures as authenticated evidence.

| Scenario | Action | Expected evidence |
|---|---|---|
| A — Empty composer | Load an idle bound conversation, wait for stable probes, move it to the background. | Composer found, `draftState=empty`, eligibility reasons show whether unsent state is still unknown. If unknown is the only blocker, click **Verificar e suspender** once; the current detector should refuse because it has no validated `empty` surface. |
| B — Selected attachment | Select a disposable file without sending. | A positive file-input signal or unknown; never claim empty. Suspension remains blocked. |
| C — Upload/staged file | Observe upload, then leave it attached without sending. | `uploadState=present` when a progress bar is found; otherwise unknown. Both block. |
| D — Remove attachment | Remove it, wait for new polls. | Counts/state change; absence remains unknown until the structure proves the staged item is gone. |
| E — Text draft | Type text without sending. | `draftState=present`; lifecycle blocks. Clear it and observe a new state. |
| F — Long response | Start a long answer and move the view behind another conversation. | Eligibility includes responding/uncertain until the existing detector confirms an allowed at-rest state. |
| G — Restore | Only after an authenticated `empty` proof permits it, suspend and restore. | Same conversation identity, login and observer; exactly one canonical view. The current implementation should not reach suspension until that proof exists. If no proof appears, stop here and return the trace. |
| H — Login/navigation | Test existing session, logout/login, provider redirect, chat/Project routes, external link and an unexpected origin. | Origin-only trace matches policy; blocked origins stay outside the ChatGPT view. No allowlist change is implied by a failed provider flow. |
